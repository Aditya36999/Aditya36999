## approach

How I think about building software.

I care about the fundamentals. Knowing why something works matters more to me than knowing that it works. When I pick up a new technology, I go one layer deeper than the docs — I want to understand the tradeoffs, not just the API.

I collaborate well and I communicate clearly. I think the best code comes from teams that talk to each other, not teams that only talk to their IDEs. I leave codebases cleaner than I found them.

I take open source seriously. If something I built has helped someone else, that is enough.
